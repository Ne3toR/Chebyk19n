# Деплой портфолио на GitHub Pages

Пошаговая инструкция. Никакого терминала, всё через сайт github.com.
Время на всё — 5–7 минут.

---

## Что внутри этой папки

```
publish/
├── index.html      ← главная страница
├── .nojekyll       ← говорит GitHub-у не обрабатывать файлы (важно!)
├── assets/
│   ├── portrait-fig.jpg
│   ├── work-statum-fig.png
│   └── work-rush-fig.png
└── README.md       ← этот файл
```

Эти файлы — всё, что нужно для сайта. Их и будем заливать.

---

## Шаг 1. Зарегистрироваться на GitHub (если ещё нет аккаунта)

1. Откройте https://github.com/signup
2. Email → пароль → username. **Username станет частью адреса сайта** —
   например, если выбрать `nikitacheb`, сайт будет на `nikitacheb.github.io/...`
   Выбирайте короткий и читаемый.
3. Подтвердите email.

---

## Шаг 2. Создать репозиторий

1. В правом верхнем углу нажмите **`+` → New repository**.
2. **Repository name:** `portfolio` (можно любое — это попадёт в URL).
3. **Public** — обязательно (Pages бесплатно работают только на публичных репо).
4. ✅ Поставьте галочку **«Add a README file»** — иначе GitHub не даст залить файлы через браузер.
5. Нажмите **Create repository**.

---

## Шаг 3. Загрузить файлы

1. На странице репозитория нажмите **`Add file` → `Upload files`**.
2. Откройте папку `publish/` на компьютере.
3. Выделите **всё содержимое папки** (не саму папку, а файлы внутри:
   `index.html`, `.nojekyll`, папку `assets` и `README.md`) и перетащите в окно браузера.
   - Если `.nojekyll` не виден — в Finder нажмите `Cmd + Shift + .`, в Windows
     включите «Скрытые элементы» в проводнике.
4. Внизу страницы — **Commit changes**.

Через 10–20 секунд файлы появятся в репозитории.

---

## Шаг 4. Включить GitHub Pages

1. В репозитории откройте вкладку **Settings** (шестерёнка справа сверху).
2. В левом меню — **Pages**.
3. В блоке **Build and deployment**:
   - **Source:** `Deploy from a branch`
   - **Branch:** `main` → папка `/ (root)` → **Save**.
4. Подождите 1–2 минуты. Обновите страницу Settings → Pages.
5. Сверху появится зелёная плашка с адресом:
   **`https://ваш-username.github.io/portfolio/`**

Готово. Откройте ссылку — сайт работает.

---

## Шаг 5. (опционально) Свой домен

Если купили домен (например `chebykin.ru` в Reg.ru):

1. **Settings → Pages → Custom domain** → введите домен → Save.
2. В панели регистратора домена добавьте DNS-записи:
   - `A` запись на `@` → `185.199.108.153`
   - `A` запись на `@` → `185.199.109.153`
   - `A` запись на `@` → `185.199.110.153`
   - `A` запись на `@` → `185.199.111.153`
   - `CNAME` запись на `www` → `ваш-username.github.io`
3. Подождите 1–24 часа, пока обновятся DNS.
4. Вернитесь в Settings → Pages, включите ✅ **Enforce HTTPS**.

---

## Как обновлять сайт потом

Поменяли картинку или текст в `index.html`:

1. В репозитории откройте нужный файл → иконка карандаша (✏️ Edit).
2. Внесите правки → внизу **Commit changes**.
3. Через 30–60 секунд изменения уже на сайте.

Или залейте новую версию через `Add file → Upload files` — старый файл
заменится автоматически (если имя совпадает).

---

## Если сайт не работает

| Симптом | Решение |
|---|---|
| 404 при открытии ссылки | Подождите ещё 1–2 минуты. GitHub Pages нужно время на первый деплой. |
| Сайт открылся, но без картинок / шрифтов | Проверьте, что папка `assets/` залита целиком и `.nojekyll` лежит в корне репо. |
| `Settings → Pages` пишет, что Pages выключены | Репо должно быть **Public**, не Private. |
| Изменили файл, но на сайте старая версия | Жёсткое обновление: `Ctrl + Shift + R` (Windows) / `Cmd + Shift + R` (Mac). |

## Про скорость в России

GitHub Pages отдаётся через CDN Fastly — точки присутствия в Москве есть,
у большинства провайдеров открывается за 0.5–1.5 секунды. У некоторых
(МТС, иногда Ростелеком) может быть медленнее, но критичных блокировок нет.

Сама страница весит ~700 КБ (в основном картинки) — после первой загрузки
браузер кэширует всё, повторные открытия моментальные.

Если в будущем нужна максимальная скорость именно по РФ — переезд на
**Яндекс Object Storage + Yandex CDN** даст ещё в 2–3 раза быстрее.
Но для портфолио GitHub Pages с запасом хватает.
